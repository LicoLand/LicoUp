# LicoUp 架构

Updated: 2026-09-25

[English](README.md) · [开发入口](../RUNBOOK.zh-CN.md)

LicoUp 将端点工作保留在本地，通过消费者定义的接口组合独立领域。
远程传输不能成为身份、审批、工作状态或历史的第二权威。

| 层 | 职责 | 依赖边界 |
| --- | --- | --- |
| 表现层 | 视图、交互、资源渲染 | 消费投影契约，不在控件中持有领域存储或原生 RPC |
| 应用与桥接 | 用例、生成 DTO、类型化命令路由 | 组合领域；传输不决定领域策略 |
| 领域 | 会话、工作流、端点和目录决策 | 依赖端口，不依赖平台机制 |
| 基础设施与平台 | 存储、进程、网络、OS 密钥托管 | 实现端口，不重新定义领域事实 |

领域是穿过这些层的垂直切片。先按[模块索引](../RUNBOOK.md#module-guides)
读取相关模块的职责、固定检查和测试目录。具体设计参考见[架构参考表](README.md)。
详细状态、字段与断言由可执行配置和测试拥有，不在索引重复维护；
声明的支持范围见生成的[兼容性](../COMPATIBILITY.zh-CN.md)。
