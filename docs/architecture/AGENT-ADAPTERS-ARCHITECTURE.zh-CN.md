# Agent 适配器边界

Updated: 2026-09-25

[English](AGENT-ADAPTERS-ARCHITECTURE.md) · [运行时模块](../modules/agent-runtime.md)

内核只消费一套当前语义外观：发送输入、接收输出、控制已接纳的轮次、处理审批。
厂商 RPC、ACP、MCP、HTTP/SSE、终端报文及上游版本差异留在适配器；不在会话或
Flutter 中保留多套 V1/V2 内核契约和厂商分支。外部协议标识只描述适配器的报文格式。

审批表达决策与范围，包括单次、受支持的持续范围或前缀，以及相应拒绝。不能把单次
授权扩大为永久授权，也不能伪装不支持的范围。保留真实能力及明确的不支持结果。
用量、价格、模型发现各有属主，不扩大核心收发消息契约。

[运行时契约](../../crates/licoup-agent-runtime/src/)和
[扩展契约](../../crates/licoup-extension-contracts/src/agent.rs)拥有可执行字段；
[兼容性](../COMPATIBILITY.zh-CN.md)投影适配器登记，不在此重复厂商与协议矩阵。

适配器解析报文，宿主管进程，会话管持久历史。禁止强制回复格式，不用沉默推断完成，
不把精确恢复悄悄改成新会话。尊重用户选择的命令和环境。

设计时以 `npm run repo:impact -- --path <变更路径>` 查询依赖。专有修改只检查相关
适配器；共享语义或传输修改覆盖消费者。边界两端在同一个完整 PR 中迁移，共享文件
只有一个属主。缺少真实验证报 warning，不伪称支持，也不因此单独阻止提交；显式要求的
真实验证逐个运行。`npm run repo:upstream` 观察官方来源元数据；页面变化需要复核，
无关的上游协议修复另开 Draft PR。
