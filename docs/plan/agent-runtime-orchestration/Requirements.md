# Local Agent Runtime and Orchestration Requirements

## Product contract

Lico Arc users need one conversation surface that can select any packaged local agent, observe its output before the turn ends, continue the same native conversation on later turns, and let a policy route or coordinate work without losing context. Adapter contributors need one complete contract and one configuration authority instead of scattered hard-coded lists, fixtures, and compile-time projections.

The target inventory is the exact set of canonical adapter manifests registered by this plan. “All agents” means every member of that set. The plan cannot close by shrinking the supported set, allowing it to be empty, or relabeling an unverified adapter as supported. If an agent framework lacks an official safe transport, its adapter Node remains blocked until an official protocol, SDK, or same-native-session integration satisfies the contract.

## Requirements

- **REQ-001 — Exact all-adapter inventory.** One canonical manifest directory defines the complete packaged adapter identity set. Runtime registry, packaging, renderer metadata, readiness, tests, and contributor tooling are generated or exact-set validated against it; no second handwritten identity inventory remains.
- **REQ-002 — Real official local forwarding.** Every registered adapter sends through an official local protocol or SDK that controls the framework's actual native session. Prompt, session identity, context reference, credentials, and private paths never enter process argv. TUI scraping, window automation, private database mutation, latest-session selection, and fixture execution cannot satisfy this requirement.
- **REQ-003 — Ordered realtime projection.** Every successful send emits a started event, ordered progressive chunks and supported structured process events before one terminal event. Every event is owned by one adapter, native session, Lico thread, and turn; duplicates, late events, and cross-turn contamination fail closed.
- **REQ-004 — Exact native continuation.** New conversation creation returns the framework's real native session ID. Every later Lico Arc send opens or resumes that exact ID and rejects empty, changed, latest, or ambiguous identity. The final native reply is committed to the same Lico thread and becomes input to later turns.
- **REQ-005 — Bounded supervised lifecycle.** A session supervisor owns process handles, stream subscriptions, cancellation, timeouts, cleanup, per-adapter concurrency, global concurrency, and bounded session state. Backpressure and failure disposition prevent duplicate dispatch after unknown outcomes.
- **REQ-006 — Unified dynamic configuration authority.** Canonical manifests, non-secret runtime overrides, routing policy, and generated projections have one documented storage model. Runtime files are schema validated, privately and atomically replaced, watched with debounce, applied as immutable revisions at message boundaries, and rolled back to the last-good snapshot on invalid reload. Secrets remain in platform-native stores or the agent framework.
- **REQ-007 — Complete adapter contribution workflow.** A contributor can investigate an official framework, fill one manifest/template, implement the declared interface, run capability and privacy checks, prove live parity, and register the adapter without editing unrelated inventories. The workflow lists every required interface, configuration field, blocker, test, and promotion rule.
- **REQ-008 — Deterministic policy routing.** At each user-message boundary, one policy revision evaluates readiness, role, capability, model, allowance, circuit state, priority, and strategy, then produces an explainable deterministic dispatch plan. Supported strategies share the same lane and session authority.
- **REQ-009 — Protected local context artifact.** A route or handoff materializes a versioned, immutable, digest-bound context package at a private local path. The destination receives that path through a typed protocol or stdin field, never argv; public history and evidence retain only opaque handles and digests. Artifact lifetime, ownership, acknowledgement, and cleanup are bounded.
- **REQ-010 — Target-aware context budget.** Before creating the artifact or dispatching a target, Lico Arc resolves the target adapter/model context limit and reserved output/tool budget, measures the selected source window, and makes a deterministic fit/overflow decision. Unknown limits fail closed or use an explicitly conservative manifest bound; they never silently truncate required sections.
- **REQ-011 — Framework-executed compression.** Overflow invokes the configured, ready compression-capable agent/framework through the same supervised lane. Compression preserves objective, current state, decisions, constraints, open items, source references, and fidelity evidence. Hierarchical compression is bounded, content-addressed, and cached by source digest, target budget, compressor identity, model, and configuration revision; failure never dispatches a lossy package.
- **REQ-012 — Bounded orchestration scheduling.** Serial, priority-fallback, parallel, and coordinator-worker strategies execute as a bounded dispatch DAG with deterministic ready ordering, per-adapter semaphores, cancellation propagation, result aggregation, and explicit partial/unknown-outcome semantics. No unbounded task, queue, transcript, cache, or process collection exists.
- **REQ-013 — Privacy and authorization.** Configuration excludes credentials and private runtime data; runtime paths and native IDs are redacted outside the local execution boundary; permission requests default to deny and use one platform-native authorization flow when credential or key access is needed. Logs, UI, receipts, and tests expose minimum structured evidence only.
- **REQ-014 — One product execution path.** GUI direct send, GUI policy routing, CLI, live acceptance, and later adapter integrations consume the same registry, readiness, session supervisor, context pipeline, and dispatch lane. Progressive events render in the current timeline; terminal replies, errors, and route disclosures update the same thread without placeholder success.
- **REQ-015 — Complete authority migration.** The new capability plan becomes the only current owner of local-agent execution, adapter lifecycle, context transfer, and orchestration. Superseded active nodes, hard-coded inventories, compile-time-only configuration paths, duplicate runners, and release-owned feature authority are removed or retired in the same delivery; the release plan consumes only the final capability receipt.
- **REQ-016 — Verifiable client delivery.** Static contracts, negative fixtures, per-adapter official-lane tests, real live two-way continuation, realtime UI, context overflow/compression/path handoff, reload/rollback, scheduler tests, privacy scans, aggregate client verification, rebuild, and launch prove the delivered product. Each implementation Node is committed separately and records its delivering commit.

## Users and workflows

1. A user selects a local agent, sends a message, sees ordered output immediately, then sends another message that resumes the same native session.
2. A user selects the orchestration target; Lico Arc evaluates the active policy, prepares a target-fit local context artifact, compresses through an eligible framework only when required, dispatches the chosen strategy, and writes real results back into the same thread.
3. An operator edits a non-secret adapter or routing configuration file; a valid revision activates at a message boundary, while an invalid revision leaves active sessions and the last-good snapshot unchanged.
4. A contributor evaluates a new framework against the adapter standard, adds one canonical manifest and one driver, and runs one documented promotion workflow.

## Scope and non-goals

Scope is the official Lico Arc desktop/mobile client, native sidecar, packaged local-agent adapters, configuration and routing policy, context artifacts, compression, UI/CLI integration, and client verification. Server policy and gateway protocol authority remain in the core repository. This plan does not implement remote arbitrary code, expose secrets in portable configuration, parse TUIs, mutate vendor state stores, redesign existing layouts, or claim store/publication completion.

## Final acceptance

The plan is complete only when every canonical adapter passes its applicable official-lane contract and the exact inventory has no blocked, unverified, or send-disabled member; direct and routed conversations show terminal-before/after ordering correctly and continue the same native ID; oversize context is budgeted, compressed by a declared ready framework, materialized as a protected local path, acknowledged, and cleaned; valid configuration reloads atomically while invalid input preserves last-good state; all strategies obey bounded scheduling and failure semantics; release consumes the capability receipt; and the rebuilt client is opened after validation.
