LicoUp 并行开发地图

当另一个开发者或智能体正在修改仓库时，这份地图告诉你：哪些功能可以安全地并行推进（文件零重叠），哪些文件是全局集成瓶颈（绝不能两方同时编辑），哪些改动必须按顺序落地。

✓ 文件不相交两个改动不触碰任何共同文件 — 唯一硬性要求
✓ 契约稳定公开 API 冻结期间，各层实现可并行演进
✓ 构建隔离Rust 与 Flutter 独立构建，跨语言仅桥接契约耦合
1

仓库拓扑：两套独立构建系统

Rust workspace（crates/）与 Flutter 客户端（apps/desktop/）相互独立；唯一跨语言面是 licoup.stdio.v1 RPC / 移动端 FFI 契约。

2

Rust workspace：8 个叶子 crate 并发开发

叶子 crate 之间零依赖，各自只有一个消费者 licoup-native。公开 API 视为冻结契约时，8 个叶子可同时推进。

CrateWorkspace 依赖并行安全性
lico-catalog-convergence—叶子 内部改动隔离；公开 API 只波及 native
licoup-protocol-bindings—叶子 同规则
licoup-client-state—叶子 同规则
licoup-endpoint-core—叶子 同规则
licoup-platform-bridges—叶子 同规则
licoup-agent-adapters—叶子 同规则
licoup-agent-runtime—叶子 同规则
licoup-conversation—叶子 宿主中立，不依赖 agent-runtime
licoup-native全部 8 个汇聚点 串行集成通道 · 所有跨 crate 接线落点

规则叶子内部随便改

  • 修改不涉及公开 API → 完全隔离
  • 与任意其他叶子并行
  • 测试在各自 crate 内

规则API 变更要成对

  • 破坏公开 API → 同一变更集同步更新 native 调用点
  • 消费新 API 的改动晚于引入方
  • 契约先定，集成后做

规则native 内部分片

  • ffi/commands 不同命令模块可并行
  • platform/ 不同驱动目录可并行
  • mod.rs 声明文件是共享热点

全局集成瓶颈：绝不两方同时编辑

以下文件几乎被每个功能域触碰。并发改动必须避开；指定单一负责人或串行处理。

apps/desktop/lib/src/application/controller/client_controller.dart

聚合所有功能域的根控制器

apps/desktop/lib/src/application/composition/built_in_layout_composition.dart

唯一允许组装 renderer 所有权 surface bundle 的文件

apps/desktop/lib/src/application/controller/assembly/… + client_component_assembly.dart

按域拆分的组装点，但集中存放且互相引用

crates/licoup-native/src/ffi/commands/mod.rs

build_command_table() 中央命令注册表

crates/licoup-native/src/{domain,platform,ffi}/mod.rs

模块声明面 — 新增模块时唯一共享热点，错峰新增

…/contracts/generated/ · …/ffi/generated/

生成桥接契约 — 串行重新生成，绝不手改

tools/verify-documentation.mjs · tools/verify-client-boundary.mjs · docs/README.md

中央验证门禁与文档索引

5

现在即可并行的组合

以下工作对当前文件不相交，可直接交给两个开发者 / 智能体并行。

工作项 A工作项 B为什么互不冲突
Rust 叶子 crate 内部改动（如 licoup-conversation）任意其他叶子 crate 改动叶子之间零依赖
native 智能体驱动（platform/cursor_driver/）native secure mesh（core/secure_mesh_*）platform / core 目录不相交
native ffi/commands/secure_mesh.rsnative ffi/commands/agent_conversation.rs命令模块不相交（避开 mod.rs）
Flutter mobile_relay 切片Flutter skill_hub 切片全部层零文件重叠
Flutter agents UI（frontend/features/agents/）Flutter settings 切片功能目录不相交
application/features/mcp（单层）application/features/messaging（单层）仅应用层，不相交
任意 Flutter UI 工作任意 Rust crate 工作构建系统独立，仅桥接契约耦合
某域测试（test/skill_hub_* 等）任意其他域测试测试文件镜像功能域切片

必须排序的组合（不可并行）

以下工作对共享文件或共享契约面，必须串行落地。

工作项 A工作项 B为什么冲突
向 domain/mod.rs 新增模块向 domain/mod.rs 新增模块编辑同一模块声明文件
重新生成 contracts/generated/重新生成 contracts/generated/生成文件是单写者
编辑 client_controller.dart编辑 built_in_layout_composition.dart全局集成文件
叶子 crate 公开 API 变更消费该 API 的 native 工作消费者必须晚于 API 变更
桥接契约形状变更（Rust + Dart）任何其他桥接契约变更跨语言契约是单写者
7

与另一个活跃智能体协同

检测到其他开发者 / 智能体正在修改仓库时，按此清单行动。

1
先查地图

按对方变更集的文件路径定位其切片，再选文件不相交的工作。

2
避开瓶颈文件

计划改动触碰第 4 节文件 → 等待或显式协调，绝不并发编辑。

3
契约优先

先引入 / 扩展网关接口或叶子契约，把串行依赖变成两个基于冻结契约的并行实现。

4
遵守提交身份规则

每个提交恰好一个已验证的人类身份；智能体只可协助，不得取代或冒认作者身份，hooks 不得绕过。

5
交接前验证

运行所属切片门禁：文档 npm run repo:docs，代码 npm run client:test / client:native:test。
